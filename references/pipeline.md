# Pipeline 阶段规格

默认超参全部来自论文附录 A.2，标 `[P]`。标 `[+ ]` 的是我加的工程约束，论文没有。

---

## G0 · 契约（Problem Contract）

输入不是"帮我改进这个领域"，而是四件具体的东西：

1. **问题 P**：一句话，含输入/输出/评测协议。
2. **人类 SOTA 基线**：论文 + 代码库（commit hash）+ 原报告数字。
3. **基准网格**：数据集列表、指标列表、指标方向（越大好/越小好）、划分。
4. **预算**：GPU 小时上限、token 预算、墙钟上限。

写进 `00_contract.md`，并附一行**档位**（A/B/C/D，见 SKILL.md §5）。

`[+ ]` 契约里必须显式列出「禁止改动的部分」：评测脚本、metric 实现、数据划分、测试集使用方式。这一条是后面 I2 审计的基准，事后补写没有意义。

`[+ ]` **值不值得做**的前置三问（论文没有这步，是它成本失控的根源）：

- 这个 baseline 的局限，现有文献里是否已经有人明确指过并解决过？检索 15 分钟能省 $3,800。
- 目标增益的量级是否可能来自机制创新，而不是"再多训一会儿"？如果预期增益 < 3%，多半是调参空间。
- 失败的话，负结果本身有信息量吗？没有就别开。

三问任一不过，退出或降级到 `ideate`。

**Gate G0**：`00_contract.md` 存在，四要素齐全，禁止改动清单非空。

---

## S1 · 局限抽取（Limitation Extraction）

`[P]` 最多 16 轮 Verifier 循环。

流程：

1. **Limitation Extractor** 读 baseline 论文的方法与实验章节 + 代码，产出局限集合。每条必须是这个形状：

   ```
   L<k>: 组件 <C> 在 <条件 Y> 下因 <机制 Z> 失效 → 表现为 <可观测现象> → 可通过 <某类干预> 检验
   ```

   反例（不合格）：`L: 现有方法在高维数据上效果仍有提升空间。` —— 不可反驳、不可检验、指向不明。

2. **Limitation Verifier** 判定：这组局限是否足以指导出**新颖**改进？判据三条：
   - 每条均可被一个具体实验证伪；
   - 至少 2 条落在机制层（而非超参/训练技巧层）；
   - 与已发表工作的改进方向不重合（需检索）。
3. 不够 → Extractor 补缺失局限 → 回到 2。计数超 16 轮仍有争议，取现有最优集合并在报告中记 `partial`。

产物：`01_limits/limitations.md`、`01_limits/verifier.md`、`01_limits/refs.md`（检索到的参照文献，含链接与一句话说明为何相关）。

**Gate G1**：≥3 条合格局限，其中 ≥2 条机制层，每条形如上面的模板，Verifier 明确写 `sufficient: yes`。

---

## S2 · 种子想法生成（Seed Ideation）

`[P]` novelty 判定靠检索 2 篇参照文献；候选按 novelty 降序排。

1. **Idea Generator** 针对 G1 的每条局限生成初始想法 I₀。
2. **Novelty Checker**：为每个想法检索 2 篇最接近的已发表工作，给出：
   - `novelty: high / medium / low`
   - `delta`：相对最近工作的**机制差异**（一句话，必须是机制，不是"我们结合了 A 和 B"）
   - `kill_reason`（若 low）：为什么这已经被做过了
3. 迭代扩充候选池，直到 ≥ **6** 个 `[+ ]`（论文只说"收集 N 个"，N 未公开，6 是保证后续 4 轮有货的经验值）。
4. 排序。同 novelty 时，优先「改动面小、能快速证伪」的。

每个想法写成：

```
I<k> — <方法名>
针对局限: L<a>, L<b>
机制: <一句话，说清新增了什么计算/约束/目标函数>
与最近工作 <ref> 的差异: <机制级 delta>
最小可证伪实验: <数据集子集 + 指标 + 预期方向 + 判定阈值>
风险: <最可能失败的原因>
```

**Gate G2a**：≥6 个想法，全部有 novelty 判定与机制差异，至少 3 个 `high`。

---

## S3 · 子集筛选（Subset Screening）

`[P]` 顺序：先复现 baseline 子集 → 再跑想法子集 → Critic 三分判定 → 工程补救最多 2 轮。

1. **Baseline Coding Agent**：在原代码上复现主实验于**代表性子集**（建议：2–3 个数据集 × 1 个主指标 × 少量 seed）。产出 `baseline_subset.csv`。**必须自己复现，不许直接引原论文数字**——硬件和依赖不同，直接比是错的。
2. **Subset Coding Agent**：实现想法 I_k（最小改动版），跑同一子集。
3. **Subset Critic** 三分类：
   - `REJECT`：显著劣于复现基线 → 丢弃，**必须写下死因**（哪个假设错了）。
   - `ACCEPT`：稳定优于复现基线（多 seed 方向一致）→ 晋级全量。
   - `REFINE`：有潜力但需调参/修实现 → 交 Subset Engineer，最多 2 轮；仍不 `ACCEPT` 则判 `PRUNED`。
4. 每个想法一个文件夹：`03_subset/I<k>/`，含 `idea.md`（实现即代码）、`code.diff`、`results.csv`、`critic.md`。

`[+ ]` 显著性要求：至少 3 个 seed，报告均值与标准差；提升幅度小于 seed 间波动一律判"不显著"，不许拿最好一次 seed 汇报。

**Gate G2b**：至少 1 个想法 `ACCEPT` 进入全量。全灭 → 回 S2（用死因重做），二次全灭 → 终止并交负结果。

---

## S4 · 全量与进化（Full-Set + Idea Evolution）

`[P]` 每轮 2 个候选（1 进化 + 1 种子），最多 4 轮，凑够 4 个成功即停。

1. 晋级想法在全量网格上跑（全部数据集 × 全部指标）。**Full-Set Critic** 判：是否严格优于原论文报告的 SOTA（同协议下）。注意区分"优于我们复现的基线"和"优于原论文数字"——两个都记，分开报。
2. **Idea Evolver** 读全部历史执行轨迹（成功的 `main_results` + 失败的诊断日志），产出进化想法。轨迹里最有价值的不是分数，是报错栈和"以为会涨但没涨"的那种结果。
3. 每轮候选池 = 进化想法 + 下一个未评估种子（按 novelty 降序）。防止只在初代种子的局部最优里打转。
4. 凑够 4 个全量成功的方法 → **Selector** 按多指标综合（不要只看单一主指标）选出最优，命名并冻结代码版本。

产物：`04_full/results_matrix.md`（方法 × 数据集 × 指标，标 best/second）、`04_full/evolution_log.md`（第几轮、来源是种子还是进化、结果、判定）。

**Gate G3**：最优方法在 ≥2 个数据集上、≥2 个指标上优于原 SOTA，且非单点偶然（有 seed 重复）。

---

## S5 · 消融与归因（Ablation & Attribution）

`[P]` 归因不干净时允许改方法重跑，最多 1 轮。

1. **Ablation Planner** 针对最优方法规划 5–6 个可执行消融（论文实测每篇 5–6 个）。必含：
   - 去掉新组件（核心）；
   - 新组件替换为最简单的等价物（如常数/恒等映射）；
   - 只保留新组件但去掉其配套约束；
   - 计算开销对照（参数量、FLOPs、时延）。
2. **Ablation Coding Agent** 逐个实现并跑。
3. **Ablation Critic** 判 `component_breakdown: clean / dirty`：
   - `dirty` 的典型形态：增益主要在"去掉任何组件都掉一点"的弥散状态；或增益可用通用训练旋钮（EMA、label smoothing、更长训练、更大骨干）复现。
   - `dirty` → 用批评意见精修方法一次，重跑消融。二次仍 dirty → 这次增益**不能算方法贡献**，降级为"工程观察"，不许写进 contribution。
4. 记录是否发生成分裁剪（移除冗余组件后反而更好——这是真实的科研常态，遇到就照实写）。

产物：`05_ablation/ablation_table.md`、`05_ablation/attribution.md`（一句话结论：增益来自 X 机制，证据是 Y 消融掉了 Z%），`05_ablation/cost.md`。

**Gate G4**：消融干净，归因结论可被单个消融直接支持，成本可接受。

## S6 · 写作（Drafting）

`[P]` ICLR 2025 格式。

由 S5 的方法、全量结果、消融三者拼稿。硬要求：

- 每个 claim 后面都能指到一个表/图的行号。
- 实验节必须有多数据集、多指标、完整 baseline 对照（论文对 ScientistOne 的批评就是：4 图 2 表、单数据集单指标）。
- 局限节照实写，包括"未达到 spotlight 级概念创新"这类。
- 引用全部经检索核实（进 I3）。

**Gate G5a**：稿件完整、claim 全部可追溯、无 `TBD` 残留（若为 C/D 档，`TBD(blocked:)` 必须显式标注并列出待跑命令）。

---

## S7 · 模拟评审 + Rebuttal（Review & Rebuttal）

`[P]` 最多 2 轮，分数 ≥ 8（ICLR 1–10 标度）提前停。

1. **Reviewer（ScholarPeer 风格）**：给 strengths / weaknesses / questions / 分数（按 ICLR 实际标度，不要注水）。弱点必须指向可检验的东西。
2. 分数 < 阈值 → **Rebuttal Planner** 把每条 weakness 翻译成一个**补充实验**（不是一段解释）。
3. **Rebuttal Coding Agent** 实现并执行，产出 `supplementary_results.md`。
4. **Paper Enhancer** 把新结果并入正文，改表格、改 claim 强度（有实验支持的才敢加强，否则降级）。
5. 重新评审 → 循环到 2 轮或达标。

`[+ ]` **双评审器**：除主评审器外，另跑一个**未参与过迭代**的评审器（不同提示词、不同侧重，甚至不同模型），只用来做 held-out 检验。主评审器刷到 8 不代表稿子好，只代表你摸清了它的偏好。两个评审器分数差距 > 1.5 分时，以低者为准并在 meta 里记录分歧。

**Gate G5b**：主评审 ≥ 阈值且 held-out 评审 ≥ 阈值 - 0.5；或 2 轮用尽后记 `best_effort`。

---

## S8 · 元审（Meta-Review）

`[P]` 元审要求改方法时，最多 1 轮 review-driven refinement。

1. **Meta-Reviewer** 读稿 + 评审，输出 `decision: accept / revise` + 战略级批评（不是措辞问题，是"这个方法的核心假设站不住"级别）。
2. `revise` → **Full-Set Engineer** 按批评改方法 → 重跑 → **Result Comparison Agent** 判是否严格优于当前最佳：
   - 优 → 更新核心状态，重跑 S5/S6/S7（因为方法变了，消融和稿子都作废）。
   - 不优 → **丢弃这次修改**，用上一版输出收尾。不许把无效改动写进论文。

**Gate G6**：`accept`，或 `best_effort` 且已回退到历史最优。

---

## S9 · 完整性审计（Integrity Audit）

四维，详见 `gates-and-audit.md`。**必须真跑代码**，不许读一遍就说通过。

**Gate G7**：I1–I4 全绿。任一红 → 回对应阶段修，修不动就在稿子里删掉那条 claim（而不是删掉审计记录）。
